# Architecture — The Collector

## Overview
Two deployables. Next.js (Vercel) calls FastAPI (Railway) over HTTPS. FastAPI owns
Supabase Postgres via async SQLAlchemy. JWT-based auth, two roles: `user`, `admin`.

```
Browser ──> Next.js (Vercel) ──HTTPS──> FastAPI (Railway) ──asyncpg──> Supabase Postgres
```

## Backend layers
`api/v1` (routers) → `services` (business logic) → `repositories` (data access) → `models` (ORM).
Cross-cutting: `core/config`, `core/security`, `core/deps`.

## Data model
```
users(id, name, email!, password, role, created_at, updated_at)
houses(id, house_number!, created_at, updated_at)
collection(id, house_id -> houses, amount, approved, created_at, updated_at)
```
(`!` = unique). All PKs uuid, timestamps timestamptz.

## Key flows
- **Login**: POST `/auth/login` → verify argon2 → JWT `{sub, role, exp}`.
- **Create user**: admin-only POST `/users`.
- **Submit collection**: user POST `/collections {house_number, amount}` → resolve/create house → row `approved=false`.
- **Approve**: admin PATCH `/collections/{id}/approve` → `approved=true`.
- **Read**: GET `/collections`.
  - user = current month only (`created_at >= date_trunc('month', now())`), sorted `created_at desc`.
  - admin = all, filter by `approved` / `house_number`. Paginated (`page`, `size`; default 10).

## Auth & RBAC
JWT bearer. `get_current_user` decodes token; `require_role` guards admin/user endpoints.
The role claim in the token is authoritative server-side; the frontend role is presentation only.

## Migrations
Alembic (async env). Initial schema migration + admin-seed data migration (env-driven credentials).
Autogenerated migrations are reviewed by hand before commit.

## Deployment
- **Railway** builds the backend Dockerfile. Env: `DATABASE_URL` (Supabase), `JWT_SECRET`, `JWT_EXPIRE_MINUTES`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`, `CORS_ORIGINS`.
- **Vercel** builds the frontend. Env: `NEXT_PUBLIC_API_URL`.

## Future extension points
Sidebar built for more entries; roles centralized; house CRUD, reporting, and a possible
migration to Supabase Auth are anticipated but out of v1 scope.
